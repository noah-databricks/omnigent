## Claude Code

### Eligibility result

The installed Claude CLI is logged in through an `api_key_helper`. Its MCP status
warns that claude.ai connectors are disabled because the API-key auth source takes
precedence. The official computer-use documentation requires all of the following:

- macOS;
- a Pro or Max subscription (not Team or Enterprise);
- authentication through claude.ai;
- an interactive session (not `-p`); and
- the built-in `computer-use` MCP server enabled interactively for the project.

This machine does not currently satisfy the claude.ai-auth requirement, so the
Claude fixture run is blocked before tool execution. Omnigent did not alter the
user's authentication, enable the server, or accept an OS permission prompt.
An interactive Omnigent-wrapped Claude session confirmed the same result: `/mcp`
listed the configured user servers plus Omnigent, but no built-in
`computer-use` entry. The session was exited without enabling any newly detected
project MCP servers.

### Consequence

Claude delivery remains gated on an eligible claude.ai-authenticated test account.
The existing transcript parser is still the expected integration point:

- assistant `tool_use` blocks become `function_call` items;
- user `tool_result` blocks become `function_call_output` items; and
- `_strip_inline_image_data` currently replaces base64 image sources before the
  output is persisted.

No production classifier or image extractor should be merged until sanitized
Claude computer-use fixtures confirm the built-in server's tool name, result
shape, approval hook behavior, failure shape, and interruption shape.

## Codex

### Runtime topology

Codex Computer Use is a plugin plus the generic `node_repl` MCP surface:

1. The installed plugin contributes the `computer-use` skill.
2. The skill requires calls to `node_repl/js`.
3. JavaScript imports `@oai/sky` and calls its macOS application APIs.
4. The older standalone `computer-use` MCP configuration is disabled and is not
   the path exercised by the current plugin.

Omnigent's session-private `CODEX_HOME` copied the user's plugin and marketplace
configuration by reference, preserved the enabled Computer Use plugin, and
started `node_repl`. It did not copy or redistribute the plugin/runtime.

### Public app-server schema

The schema was generated by the installed public command:

```text
codex app-server generate-json-schema --experimental --out <temporary-directory>
```

The `mcpToolCall` item contains these fields:

```json
{
  "type": "mcpToolCall",
  "id": "exec_sanitized",
  "server": "node_repl",
  "tool": "js",
  "status": "inProgress",
  "arguments": {},
  "appContext": null,
  "pluginId": null,
  "result": null,
  "error": null,
  "durationMs": null
}
```

The schema allows `status` values `inProgress`, `completed`, and `failed`.
Completed results contain an MCP `content` array plus optional `_meta` and
`structuredContent`. Errors contain a required string `message`.

`item/started` and `item/completed` wrap the item with `threadId`, `turnId`, and a
millisecond lifecycle timestamp. `item/mcpToolCall/progress` contains `threadId`,
`turnId`, `itemId`, and a string `message`.

### Observed in-progress call

The harmless TextEdit inspection produced an actual in-progress item with:

- `server: "node_repl"`;
- `tool: "js"`;
- `pluginId: null`;
- `appContext: null`;
- arguments containing a bounded display title and JavaScript that imports
  `@oai/sky` and calls `sky.get_app_state({ app: "TextEdit" })`.

The call then stopped at the native Codex prompt:

```text
Allow Computer Use to use "TextEdit"?
```

The choices were one-time, session-wide, permanent, or cancel. Omnigent's generic
policy evaluation ran for the MCP call, but the per-app Computer Use approval
remained in the Codex TUI. This is the required authoritative fallback.

### Observed completed results

Both the text-only and image calls completed with `pluginId: null` and
`appContext: null`. Their result-level metadata supplied the authoritative
Computer Use identity:

```json
{
  "_meta": {
    "codex/toolSurface": {
      "kind": "computerUse",
      "app": {
        "kind": "appId",
        "appId": "com.apple.TextEdit"
      }
    }
  }
}
```

The text-only result contained one standard MCP text content block. The image
result contained text and image blocks in the same `content` array. Its image
block used the standard MCP shape:

```json
{
  "type": "image",
  "data": "<base64 omitted>",
  "mimeType": "image/png",
  "_meta": {
    "codex/imageDetail": "original"
  }
}
```

The repository fixture records only the original encoded length; raw image data
was removed by the listener before anything was written.

### Failure, interruption, and progress

A deliberate read-only failure produced `item/completed` with:

- `status: "failed"`;
- `error: null`;
- the failure text in `result.content`; and
- the same authoritative `codex/toolSurface.kind: "computerUse"` result metadata.

Code must therefore key terminal failure on `status`, not on the presence of an
`error` object.

Interrupting a running read-only call produced `item/started`, then
`turn/completed` with `turn.status: "interrupted"`. It did not produce an
`item/completed` event. A later `thread/read` still returned that tool item as
`status: "inProgress"` with no result or Computer Use metadata. The adapter must
use the terminal turn edge to settle any still-running cards for that turn; it
must not wait indefinitely for an item completion that may never arrive.

No `item/mcpToolCall/progress` notification was emitted by any successful,
failed, or interrupted call. The public schema includes that notification, so a
generic adapter may support it with a schema-derived synthetic test, but the UI
must not assume progress messages or a specific cadence.

### Classification implications

The started event did not carry `pluginId`, `appContext`, or result metadata, so
the presentation classifier needs a provisional start rule and an authoritative
completion rule:

1. At start, accept an explicit future allowlisted `pluginId`/`appContext`
   Computer Use identity when present.
2. Otherwise require `server == "node_repl"`, `tool == "js"`, and a bounded scan
   of arguments for the documented `@oai/sky` import or an allowlisted `sky` API
   call (`get_app_state`, `list_apps`, `click`, `drag`,
   `perform_secondary_action`, `press_key`, `scroll`, `select_text`, `set_value`,
   or `type_text`). This provisional classification is only for the running card.
3. At completion, treat `result._meta["codex/toolSurface"].kind ==
   "computerUse"` as authoritative and take the app identity from its `app`
   object when valid.
4. Treat uncertain cases as ordinary generic MCP calls. A completion may correct
   a provisional classification in either direction.

This classification changes presentation only. It must never grant permissions,
change execution, or bypass a vendor prompt. The optional action label can come
from the bounded `title` argument. A literal `app` string may be extracted on a
best-effort basis, but failure to identify an app must not suppress the tool card.

### Frame semantics

`sky.get_app_state` returns a local screenshot URL to the JavaScript caller, but
that URL is not automatically an MCP image result. The current Computer Use skill
usually writes the accessibility tree as text. It emits an MCP image block only
when the agent explicitly calls `nodeRepl.emitImage(...)`.

Therefore the UI can promise only the latest image block actually exposed by an
observable MCP result. It cannot promise a screenshot for every action or infer
that the local screenshot URL is readable by Omnigent. Text-only Computer Use
calls must remain valid and render without a preview.

## Fixtures and provider status

Sanitized Codex fixtures live in
`tests/fixtures/codex/computer_use/` and cover start, text-only completion, mixed
text/image completion, failed completion, and interruption. Their README records
the sanitization rules and the absence of live progress notifications.

The public Codex interface is sufficient for a Codex-first implementation; it
requires neither a private desktop API nor an Omnigent-owned control runner.
Claude discovery remains deferred until an eligible claude.ai Pro/Max account is
available. The Claude adapter stays out of production scope until its equivalent
fixture set exists.
